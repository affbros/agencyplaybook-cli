# Changelog — apb-gads-researcher

All notable changes to `apb-gads-researcher` (the read-only Google Ads history,
market and opportunity workbench; `historical-alpha-001`) are documented here.

This is a **separate release line** from `apb` (`CHANGELOG.md`, tags `v*`) and
`apb-gads` (`CHANGELOG-gads.md`, tags `gads-v*`). `apb-gads-researcher` ships
on its own `0.1.x` version line with tags `gads-research-v*`
(`.github/workflows/release-research.yml`), mirroring `apb-gads`'s pattern —
see `rust/gads/crates/ads-research/Cargo.toml`.

Format loosely follows [Keep a Changelog](https://keepachangelog.com/).

## [0.1.4] — 2026-09-25

- Policy: intent clusters about payday / title / pawn loans (prohibited by Google Ads in the US) are rejected with `policy_blocked` (visible in `rejected_alternatives` with the matched rule, `n_policy_blocked`); `plan` refuses them with exit 3, and never emits a keyword its own negatives would block.
- `competitors analyze` without a domain picks your added domains, then discovered domains by score, excluding platforms the discover filter drops.
- ROAS plans: target ROAS carried from `--target-roas`, experiment kill/scale thresholds in ROAS terms, and text that matches the spec's bidding strategy.

## [0.1.3] — 2026-09-25

- `plan`: RSA headlines and descriptions are de-duplicated (case-insensitively) after they are fitted to length; truncation could make two seeds identical, which `apb-gads recipe build` rejects (`rsa_headline_unique`).

## [0.1.2] — 2026-09-25

- `market refresh --scope opportunities` priced nothing on real workspaces: it skipped every label equal to its cluster id, but the cluster id is the representative search term. It now enriches those terms.

## [0.1.1] — 2026-09-25

Fixes from the first full real-account run of 0.1.0.

- `plan`: intent-cluster, device and hour opportunities now get the account's historically targeted, policy-permitted geos (previously none, so `apb-gads recipe build` rejected them with `geo_required`). Keywords and headlines come from the account's mined search terms; campaign names use readable labels instead of raw ids.
- `opportunities`: each opportunity appears once (duplicates across grain tiers are merged; `n_duplicates_merged`). Conversion value now flows into segment ROAS (it was always 0). New `--target-roas` (also on `economics` and `analyze readiness`). The market block reads fresh cached DataForSEO data without needing credentials.
- `analyze readiness`: checks the workspace's own account instead of the SaaS default, reads what it can from the workspace, and reports `not_assessed` instead of `ok` when there is no data.
- `market refresh`: the cost estimate now matches what DataForSEO charges and the cap is enforced after every call; new `--scope opportunities` prices the stored opportunities' terms.
- `competitors discover`: requests organic and paid results, parses the real response shape, filters out platforms/marketplaces/government/encyclopedia/social/news domains (`n_filtered`), and every candidate cites valid evidence.
- `explain` / `opportunity` / `plan` given a rejected-candidate key explain that only confirmed opportunities have ids.
- `--config` help text: `APB_API_KEY` is still required for entitlement on public builds.

## [0.1.0] — 2026-09-25

First public release of `apb-gads-researcher` (historical-alpha-001, 31 sprints).
Note: `market` via the SaaS proxy requires the `/gads/market/*` API rollout; local DataForSEO credentials work now.

- `rust/gads/docs/researcher/` — the complete `--help`-derived CLI reference,
  generated by `rust/gads/scripts/gen_researcher_docs.py` (19 pages: README +
  18 top-level commands, 28 leaf commands total). `--check` drift mode wired
  into `.github/workflows/gads-quality.yml` as a hard gate.
- `.github/workflows/release-research.yml` added (copy of `release-gads.yml`,
  tag prefix `gads-research-v*`, binary `apb-gads-researcher`) — **not yet
  tagged**; no `gads-research-v*` tag has been pushed.

No tagged release yet. The crate (`ads-research`, `apb-gads-researcher`
binary) has shipped incrementally across `historical-alpha-001` sprints
ha-01 through ha-19 without a version bump; the first tagged release will
open this file's first dated entry.
